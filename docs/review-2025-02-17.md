# Taskify Architecture Review (2025-02-17)

## Snapshot
- Scope: Spring Boot 3.5 backend delivering task/project management APIs across web, application, domain, infrastructure, and supporting configuration modules.
- Inputs: Source review across core packages, build tooling, database schema, and automated tests.
- Focus: Surface correctness gaps, security posture, design cohesion, and opportunities to streamline developer workflow.

## Highlights
- Rich domain aggregates enforce invariants and emit domain events, keeping business rules close to the model.
- Application services provide clear transactional boundaries, lean on injected clocks/UUID suppliers for deterministic testing, and consistently feed the activity log.
- MapStruct mappers keep controllers slim and DTO mapping declarative.
- Test suite covers the layers with both unit and Testcontainers-powered integration checks (e.g. `src/test/java/com/example/taskify/application/service/TaskServiceTest.java`, `src/test/java/com/example/taskify/infrastructure/persistence/jpa/adapter/TaskRepositoryAdapterIntegrationTest.java`), supporting the JaCoCo gate configured in Maven.

## Findings & Recommendations

### Security
- **[High] Actuator endpoints unintentionally exposed.** The API chain only matches `/api/**` (`src/main/java/com/example/taskify/config/security/SecurityConfig.java:28`), so every other path (including `/actuator/**`) flows to the permissive fallback chain (`src/main/java/com/example/taskify/config/security/SecurityConfig.java:47`) and bypasses authentication. Introduce a dedicated matcher for actuator routes (e.g. `/actuator/**`) with explicit authorisation, or collapse to a single chain that handles both API and actuator rules.
- **[Medium] Context path skews header enforcement.** `ActorHeaderAuthenticationFilter` checks `request.getRequestURI().startsWith("/api/")` (`src/main/java/com/example/taskify/config/security/ActorHeaderAuthenticationFilter.java:26`). When the app is mounted under a context path (e.g. `/taskify/api/...`), the check fails and requests skip authentication. Prefer `getServletPath()` or Spring’s `RequestMatcher` to ensure the filter runs whenever the servlet path starts with `/api/`.

### Web Layer
- **[High] Comment deletion ignores route scoping.** `CommentController.deleteComment` only passes the comment ID to the service (`src/main/java/com/example/taskify/web/CommentController.java:52`), and `CommentService.deleteComment` removes the record without verifying it belongs to the `taskId` in the URL (`src/main/java/com/example/taskify/application/service/CommentService.java:74`). A crafted request could delete any comment the caller knows by UUID. Resolve by loading the comment, asserting `existing.taskId().equals(taskId)`, and returning 404 when it mismatches.
- **[Medium] Error mapping depends on string parsing.** `ApiErrorHandler` infers HTTP 404 solely from the exception message contents (`src/main/java/com/example/taskify/web/ApiErrorHandler.java:27`). This is brittle; message wording changes (or localisation) could silently flip status codes. Consider domain-specific exceptions (e.g. `NotFoundException`) or an error catalog to decouple behaviour from message text.

### Application Layer
- **[Medium] Tag creation pre-check misses trimmed duplicates.** `TagService.createTag` calls `existsByName(name)` before normalising input (`src/main/java/com/example/taskify/application/service/TagService.java:31`). Supplying `"  Demo  "` passes the duplicate check but is trimmed to `"Demo"` in `Tag.create`, provoking a unique-key violation at the database. Trim (and possibly normalise case) ahead of the existence check, or handle duplicate constraint violations gracefully.

### Infrastructure & Build
- **[Medium] OpenAPI generation profile broken.** The Maven `openapi` profile executes `${project.basedir}/scripts/generate-openapi.sh` (`pom.xml:304`), but the script is absent from `scripts/`. Either restore the generator script or update the profile to the current OpenAPI build process to keep docs reproducible.

### Developer Experience
- **[Low] Activity taxonomy is partial.** `ActivityCodebook` only covers task and comment events (`src/main/java/com/example/taskify/application/service/ActivityCodebook.java:8`). If project/tag/user events are on the roadmap, codify their constants up front to avoid diverging payload shapes.
- **[Low] Consider consolidating duplicate audit updates.** Some operations call multiple domain mutators in succession (e.g. rename + schedule in `ProjectService.updateDetails`). While functionally correct, this results in back-to-back `updatedAt` writes. Wrapping related domain updates in a single method could make auditing intent clearer, though this is a stylistic call.

## Suggested Next Steps
1. Rework the security configuration so actuator endpoints and any future non-API routes receive the intended authz treatment.
2. Tighten comment deletion by enforcing task/comment association and extending tests to cover the mismatch scenario.
3. Replace message-driven HTTP status derivation with explicit exception types or an error code registry.
4. Normalise tag input ahead of duplicate checks and add a regression test covering whitespace/letter-case variants.
5. Restore or retire the `scripts/generate-openapi.sh` tooling to keep the Maven `openapi` profile executable. *(Addressed: script restored in `scripts/generate-openapi.sh`.)*
